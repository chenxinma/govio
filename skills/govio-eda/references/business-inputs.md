# 业务输入：维度与口径清单

EDA 的两个机制（维度聚合画像、覆盖漏斗）依赖业务语义输入。这些内容**不由 skill 内置**，在澄清阶段向用户收集，记入 Plan 文档的"维度与口径清单"小节，随探索迭代修订。

边界划分：

| 类别 | 内容 | 处理方式 |
|------|------|---------|
| **业务输入** | 码值语义、维度含义、口径定义（什么算有效记录）、归因规则 | 运行时由用户提供 |
| **通用机制** | 聚合 SQL 骨架、长表派生、覆盖统计、漏斗渲染 | skill 内置（见各 phase 文档） |

## 维度定义表（维度聚合画像用）

```markdown
### 维度定义（数据集: {df_name}）

| 维度列 | 展示名 | 码值/归并规则 | NULL 展示值 | 度量 |
|--------|--------|--------------|------------|------|
| order_status | 订单状态 | 见下方 CASE | - | COUNT(DISTINCT order_id) |
| customer_tier | 客户等级 | = 'VIP' -> 重点客户，else 普通 | - | 同上 |
| region | 所属区域 | 无 | 空白 | 同上 |
```

维度表达式的四种形态（业务输入的落点）：

| 形态 | 表达式模式 | 示例 |
|------|----------|------|
| 直接列 | `col` | `region` |
| 码值解码 | `CASE col WHEN 'v' THEN '语义' … ELSE '其他' END` | order_status '30'/'14' -> 已完成/已取消 |
| 归并分组 | `CASE WHEN col IN (…) THEN '组A' ELSE '其他' END` | 客户等级归并为重点/普通 |
| NULL 展示 | `COALESCE(col, '展示值')` | region 空白 |

## 覆盖口径定义表（覆盖漏斗用）

```markdown
### 覆盖口径定义

| 项 | 值 |
|----|-----|
| 全集 | df_order，口径谓词: `is_deleted = 0 AND customer_id IS NOT NULL` |
| 覆盖目标 | df_invoice（目标键列: order_id） |
| 关联键 | df_order.order_id = df_invoice.order_id |
| 归因分层（有序） | 1) 无客户关联 -> 无关联客户；2) else -> 未开票 |
```

要点：

- **口径谓词**定义什么记录算进全集（如"有效记录 = 未删除 + 有关联客户"）
- **归因分层**是有序规则，先命中的先归类，建议 ≤ 3 层
- 覆盖目标键列**必须先去重**（防 1:N 膨胀，SQL 骨架已内置）

## 兜底路径

用户给不出输入时的降级：

- **无维度定义** -> 执行 Phase 1 字段级画像（4a-4d），从 4c Top 值结果中挑低基数分类列，**提议为候选维度**请用户确认语义后，再进入维度画像
- **无覆盖口径** -> 只做 Phase 3 常规匹配率检查（Step 1-4），不做漏斗
