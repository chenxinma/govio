# Govio 数据治理知识图谱

本 Skill 是数据治理查询的入口点，负责识别用户需求类型并路由到对应子 Skill。

## 全局约束

- 所有 govio 操作只通过 `govio-cli` 完成；**未经用户明确授权，不得直连读写底层数据库**，也不得手写或修改 `--output` 目录下的 CSV
- 命令语义以各子 Skill 与 `--help` 为准，不通过阅读 govio 源码 / git 历史反推
- 元数据导入不在画布展示，只做文字结果说明（展示表结构属用户主动查询场景 → `govio-query`）

## 子 Skill

| Skill | 用途 | 触发场景 |
|-------|------|----------|
| `govio-meta` | 知识图谱维护 | 导入元数据/应用/标准/关系/指标、更新图库、推荐数据标准 |
| `govio-query` | 元数据/指标查询 | 查询应用、表、字段、数据标准、指标数据、维度分析 |
| `govio-observe` | 数据探查与比对 | 查看数据源、加载数据、探索关系、比对数据、生成图表 |
| `govio-eda` | EDA 分析 | 数据集画像、推断关联、核查关联、一致性检查 |
| `govio-reconcile` | 多源数据对账 | 跨系统实体对账、关联覆盖分析、多维度统计画像 |

## 需求路由

```
用户请求
  │
  ├─ 包含"导入元数据"、"更新图库"、"推荐标准"等维护关键词
  │   └─ 路由到 govio-meta
  │
  ├─ 包含"指标"、"收入"、"签约"、"金额"、"YTD"等业务指标关键词
  │   └─ 路由到 govio-query (指标问数)
  │
  ├─ 包含"应用"、"表"、"字段"、"结构"等元数据关键词
  │   └─ 路由到 govio-query (元数据查询)
  │
  ├─ 包含"数据源"、"加载"、"比对"、"探索关系"、"图表"等探查关键词
  │   └─ 路由到 govio-observe
  │
  ├─ 包含"探查"、"画像"、"一致性"、"数据质量"等 EDA 关键词
  │   └─ 路由到 govio-eda
  │
  ├─ 包含"对账"、"跨系统比对"、"关联覆盖率"等多源对账关键词
  │   └─ 路由到 govio-reconcile
  │
  └─ 不确定 → 先询问用户意图
```

### 路由规则

**路由到 `govio-meta` 的场景**：
- 知识图谱维护："导入元数据"、"更新图库"、"导入指标/关系"、"推荐数据标准"
- 后端管理：`govio-cli backend`（查看）/ `govio-cli onboard`（初始化）

**路由到 `govio-query` 的场景**：
- 指标问数："本月账单收入是多少"、"签约覆盖率"、"按部门统计"、"月度趋势"
- 元数据查询："有哪些应用"、"AEP 有哪些表"、"T_INVOICE 表的字段"、"字段的数据标准是什么"

**路由到 `govio-observe` 的场景**：
- 数据探查："查看有哪些数据源"、"加载客户表数据"、"探索表间关系"
- 数据比对："比对两个表的数据"、"验证数据迁移结果"
- 数据可视化："画个柱状图看看销售趋势"

**路由到 `govio-eda` 的场景**：
- 数据探查："帮我探查一下这批数据"、"分析这些表的结构和关系"
- 数据质量："检查数据一致性"、"发现跨系统的数据差异"
- 关联分析："这些表之间有什么关系"、"验证外键是否正确"

**路由到 `govio-reconcile` 的场景**（多源实体对账，五阶段交互流程）：
- 跨系统对账："订单系统与客户主数据对账"、"两边的客户能不能对上"
- 覆盖分析："关联覆盖率多少"、"哪些订单找不到对应客户"
- 维度画像："按区域/渠道拆分对账结果"
- 与 `govio-observe` 的区分：单次的两表比对/数据探查走 `govio-observe`；需要「实体集合 + 关联链 + 筛选口径」的多源对账分析走 `govio-reconcile`

## 名称解析

当 prompt 包含中文系统名（如"报价单中心系统""薪税系统"），**必须先 Grep 确认标准英文代码**：

- Grep 搜索 `assets/names/node_names.md`
- 或 Grep 搜索 `assets/names/` 下按应用分的文件

## 后端

后端类型通过 `govio-cli backend` 获取（由 `govio-cli onboard` 设置）。

| 后端 | 查询语言 | 使用场景 |
|------|---------|---------|
| `falkordb` | Cypher | govio-query 的元数据/指标查询 |
| `ladybug` | Cypher | 本地嵌入式 `.lbdb` 文件查询 |
| `networkx` | Python | 本地 GML 文件查询 |

## Cypher 语法规范

- 属性值**必须用双引号**：`{name: "AEP"}` 而非 `{name: 'AEP'}`
- 必须以 `MATCH` 开头
- **必须包含 `LIMIT 300`**（明确需全量除外）
- Col 节点用 `column_name` 属性表示列名，不要用 `name`

## 查询终止策略

对同一语义目标最多 **3 次尝试**，逐步放宽：

1. 精确匹配（`name: "银行"`）
2. 模糊/包含匹配（`name CONTAINS "银行"`）
3. 同义词扩展（`金融`、`bank` 等）

3 次后仍无结果，**必须停止**并告知"知识图谱中未找到相关数据"。

## 排除场景

以下场景**不要**触发本技能：
- 数据迁移脚本编写
- 代码调试/修复
- 功能模块开发
- 数据库运维操作
