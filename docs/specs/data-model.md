# Data Model -- Node Types, Edge Types, CSV Conventions

## Identity Format

所有表/列引用使用**带数据源前缀的全限定标识**，跨数据源全局唯一：

| 对象 | 格式 | 示例 |
|---|---|---|
| 表 | `<datasource_name>.<schema>.<table>` | `hr_prod.ihrodb.employee` |
| 列 | `<datasource_name>.<schema>.<table>.<column>` | `hr_prod.ihrodb.employee.emp_id` |

- `full_table_name` 属性即表全限定标识，`column` 属性即列全限定标识
- metric 定义（`source_tables[].full_table_name`）与 relationship 定义（`PhysicalTable`）均使用该格式
- 不同数据源中的同名 `schema.table`（如 `hive_prod.dw.orders` 与 `mysql_bi.dw.orders`）是不同的表，生成不同节点

> 不提供从旧模型（Application/USE、`schema.table` 标识）到新模型的迁移路径，旧图与旧 CSV 需按新模型重新生成。

## Node ID Format

Node IDs are **deterministic 10-character strings**, not sequential integers.

### Format

```
<2-char type prefix><SHA256(business_key)[:8] uppercase hex>
```

| Node Type | Prefix | Business Key Column | Example |
|---|---|---|---|
| PhysicalTable | `PT` | `full_table_name` | `PTA1B2C3D4` |
| Col | `CO` | `column` | `COE5F6G7H8` |
| Datasource | `DS` | `datasource_name` | `DS9F6A2B1C3` |
| Standard | `ST` | `standard_id` | `STM3N4O5P6` |
| Metric | `ME` | `code` | `MEQ7R8S9T0` |
| Dimension | `DI` | `code` | `DIU1V2W3X4` |

Generated by `govio.metadata.node_id.make_id()` and `assign_node_ids()`.

## Node Types

| Node | Key Attributes |
|---|---|
| PhysicalTable | `full_table_name`, `schema`, `table_name`, `name`, `data_entity_type`, `database_name` |
| Col | `column`, `column_name`, `name`, `full_table_name`, `data_type`, `dtype`, `size`, `precision`, `scale`, `order_no` |
| Datasource | `datasource_name`, `name`, `source_type`, `filter` |
| Standard | `standard_id`, `name`, plus dynamically pivoted attribute columns |
| Metric | `code`, `name`, `business_definition`, `type`, `formula`, `unit`, `data_type`, `owner`, `update_frequency`, `statistical_scope`, `time_scope`, `source_layer`, `version`, `effective_from` |
| Dimension | `code`, `name`, `granularity`, `values_example` |

### Datasource

逻辑数据来源的信息记录节点。与 `~/.govio/config.yaml` 中 observe 的 `datasources` 按 `datasource_name` 对应，但**不记录任何可达性/连接状态**——连接配置与元数据导入是两条独立时间线，图上只保存治理侧的事实。

| Attribute | Type | Description |
|---|---|---|
| `datasource_name` | string | business key，全局唯一；来自 datasource 声明文件或导入参数 |
| `name` | string | 显示名，缺省取 `datasource_name` |
| `source_type` | string | 数据源类型，开放取值（见下） |
| `filter` | string (JSON) | 治理范围声明，序列化的 filter 对象 |

`source_type` 已知取值：`duckdb`、`tds`、`mysql`、`postgres`、`oracle`、`hive`、`trino`；不做 enum 封闭，允许扩展。

#### filter

```json
{
  "schemas": ["ihrodb", "IHRO_BILL"],
  "include_tables": ["*"],
  "exclude_tables": ["tmp_*", "bak_*"]
}
```

| Field | Required | Semantics |
|---|---|---|
| `schemas` | 是 | 纳入治理范围的 schema 列表 |
| `include_tables` | 否 | 表名白名单 glob，缺省 `["*"]` |
| `exclude_tables` | 否 | 表名黑名单 glob，优先级高于 include |

- 匹配语法：`fnmatch` glob（`*`、`?`、`[seq]`）
- 大小写不敏感
- **TDS 导入**：`filter` 是实际执行的过滤依据（`filter.schemas` 并集决定抽取范围）
- **非 TDS 导入**：实际过滤由 CLI `--schemas` 执行，`filter` 记录本次生效的范围

## Edge Types

| Edge | From | To | Extra Attributes |
|---|---|---|---|
| HAS_COLUMN | PhysicalTable | Col | -- |
| OWNS | Datasource | PhysicalTable | -- |
| COMPLIES_WITH | Col | Standard | -- |
| RELATES_TO | PhysicalTable | PhysicalTable | `relationship_type`, `description`, `source_columns`, `target_columns` |
| USES_TABLE | Metric | PhysicalTable | -- |
| REFERS_COLUMN | Metric | Col | `role` |
| DERIVED_FROM | Metric | Metric | -- |
| DIMENSION_USED | Metric | Dimension | `usage_type` |
| SUPERSEDES | Metric | Metric | `change_description` |

`OWNS` 表示数据源对物理表的治理归属（元数据导入范围内每张表一条），由 `meta meta` 生成，每张 `PhysicalTable` 恰好被一个 `Datasource` 拥有。

## Reserved for Future

- Node: `Calculation`
- Edges: `CALCULATED_BY`, `BASED_ON`

## CSV Conventions

FalkorDB/Ladybug bulk-import header format. Node IDs are 10-char strings (not sequential integers).

### Node CSVs

```
:ID(NodeType),attr1,attr2,...
PTA1B2C3D4,值1,值2,...
```

- Column 1: `:ID(NodeType)` -- deterministic string ID (prefix + SHA256 hash)
- Remaining columns: node attributes
- `Datasource.csv` 的 `filter` 列存放 JSON 字符串（RFC 4180 引号转义）

### Edge CSVs

```
:START_ID(NodeType),:END_ID(NodeType),attr1,...
PTA1B2C3D4,COE5F6G7H8,值1,...
```

- Column 1: `:START_ID(SourceType)` -- source node string ID
- Column 2: `:END_ID(TargetType)` -- target node string ID
- Remaining columns: edge attributes

### Naming Convention

- Node files: `{NodeType}.csv` (e.g., `PhysicalTable.csv`, `Datasource.csv`)
- Edge files: `{EDGE_TYPE}.csv` (e.g., `HAS_COLUMN.csv`, `OWNS.csv`)

## Graph Output

`gen_networkx.py` reads CSV files and produces a GML file (`ontology.gml`) containing a `nx.DiGraph` with all nodes and edges.

```python
build_graph(csv_dir: str, output_gml: str, incremental: bool = False)
```

When `incremental=True`, merges new CSV data into existing GML graph instead of full rebuild.
